1️⃣ Purpose

Consolidate instrument control, script tracking, and live analysis into a single tabbed Instruments workspace.
Eliminate WebSocket resets and page-based state loss while improving visibility across multiple connected devices (XP2 / XP3 / VP1 etc.).

2️⃣ Goals

✅ Keep WebSocket connections alive across tabs (no unmount).
✅ Persistent UI state (scripts, run state, current line).
✅ Unified layout:

Tabs = instruments

Script viewer + console

Bottom toggleable Potential Stat chart

Metadata box (per instrument)
✅ Integrated dashboard with toggle fix and metadata builder connection.

6️⃣ Functional Requirements
Tabs & WebSockets

Each tab mounts once; WS connection per device.

Tab header text uses serial (e.g., ED-XP3-104).

Max tabs = 5 (default) | configurable to 10.

Reconnect banner on disconnect (“Reconnecting…”).

Script Viewer

Deterministic capture logic:

Start → !gpbuf_print 0

Stop → device prompt or backend-finished event or 1.2 s idle.

Normalize → remove CR, collapse dupes, strip pre-echo.

Highlight script-position line.

Persist to store (Zustand + persist).

Console

Adjacent panel to viewer.

Supports multi-instrument send (checkbox targeting).

Buttons: Run, Stop, Send.

Metadata Box

Displays tags from Dashboard Experiment Builder.

Editable inline (using TagEditor logic).

Box under script pane for clarity.

Potential Stat Panel

Shared bottom chart.

Shows multi-instrument current/time traces.

Placeholder for RTIA A/B/C readings.

Toggle visibility (collapse arrow).

Future: real data from data-sample WS event.

Right Drawer (Script Upload)

Lists scripts from library.

Multi-select instruments + scripts.

Upload buttons: “Upload Selected” / “Upload All Visible”.

Progress per instrument tab.

7️⃣ State Management

Zustand Store Shape

{
  scanInProgress: boolean;
  connectedDevices: string[];
  perDevice: Record<Serial, {
    uploadedScript: string;
    uploadedScriptReady: boolean;
    currentLine: number;
    isRunning: boolean;
    captureActive: boolean;
    metadataTags: MetaTag[];
    showInChart: boolean;
    rtiaChannel?: 'A'|'B'|'C';
  }>;
}


Rules

Only store writes to localStorage via persist.

Components never touch localStorage directly.

8️⃣ Backend Contract (unchanged)

REST: /api/devices, /api/devices/connect, /api/devices/scan

WS: /ws/device/{serial} → events data-sample, temperature, script-output, script-position, log, script-uploaded

Optionally emit {type:"log", event:"backend-finished"} after upload.
No backend edits required.
